## [0.2.0] - 2026-10-12

Hardening release: production-grade safety gates, a real-hardware path, free models, and
study tooling.

### Security / safety
- **The rule check is now a hard gate**: `rules.require_safe` runs inside `layout.place()`,
  `wiring.build_guide()` and before every physical stage of the agent.
- **The photo check gates power**: USB power only after the latest wiring passed. Any
  physical change resets this.
- Every physical fix now happens with USB unplugged and is followed by a photo check, a
  safe-idle smoke test and a reflash. Before, fixes found by the signal walk or the I2C/DHT
  checks re-powered without checks, and some were made while powered.
- Before any wiring, the bare Pico gets safe-idle firmware, so an old `main.py` cannot drive
  the new circuit.
- New spec screen refuses mains, batteries, >5 V, >500 mA, motors, relays, heaters and lasers.
- Hard ceilings for all electrical limits. The YAML can tighten them, never loosen them.
- Rule-checker bypasses closed: direct use of Pico power/control pins, the fixture's
  unmeasured `V3_SRC` and INA nets, power-alias net names, unknown part kinds, fixture parts
  as design parts, buttons shorting supplies, 5 V into a GPIO through any part or an
  on-board pull-up (DHT22), NPN collectors with no load, wired GPIOs missing from `pin_map`,
  and loosely typed design JSON.
- New rules: `shorted_part`, `led_current`, `resistor_power`; `overvoltage`, `transistor`
  and `rail_budget` extended (USB total budget). Worst-case LED current now uses Vf minimum.
- Firmware linter (`fwlint.py`): pins must be literal or module constants from the checked
  `pin_map`; no button pins as outputs; no `machine.mem*`, deep sleep, overclocking,
  `eval`/`exec`, dunder access, star imports, or I2C/SPI/UART on default pins.
- Model diagnoses can only *restore the approved plan* (`validate_fix`). The text shown to the
  person is generated by code.
- Model test plans are validated (`validate_test_plan`). The signal walk never toggles a
  button pin or an unlisted GPIO.
- MCP `flash_firmware` requires a rule-checked design and lint-clean code. New
  `check_design` tool.
- Web UI: no model text inserted as HTML, strict CSP, upload type and size checks, and an
  access token when bound beyond localhost.

### Added
- `hands run <gadget|spec> --sim|--real`: the full loop on real hardware with a person at the
  terminal.
- `hands doctor`: environment check with exact fixes. `hands bringup`: guided first-time
  hardware check (LED, INA219 fixture, logic-analyzer self-test, camera).
- Real bench: Pico port discovery (USB VID 0x2E8A) on macOS, Linux and Windows, with BOOTSEL
  detection; mpremote retries with backoff on transient errors; sigrok-cli presence and device
  checks with actionable errors; camera via OpenCV, fswebcam, imagesnap or a phone photo
  (`--camera prompt`).
- On-Pico current monitor (`firmware/hands_bench.py` + `main.py` shim): reads the INA219
  while the program runs, with an `mpremote exec` fallback.
- Model providers: an OpenAI-compatible adapter (stdlib only; Ollama, LM Studio, llama.cpp,
  vLLM) with JSON mode, timeouts and retries; `--model`, `--base-url`, `--vision-model`;
  `ConsoleVision` when no vision model is available.
- Web UI rewrite: accessible single page with step diagrams, a progress bar, phone photo
  upload, a self-check list, and a red "do not plug in" panel until power is safe.
- Schema-versioned JSONL events (ISO timestamps, participant ids, interventions,
  power on/cut); `hands report --format md` study report; `docs/study-protocol.md` with a
  consent template.
- Packaging: `hands` entry point, ruff, mypy (strict core), pytest-cov (85% gate), GitHub
  Actions CI (3.11/3.12/3.13 + macOS/Windows), Dockerfile, Makefile, `hands rules`.
- Docs: README rewrite, `docs/safety.md` with datasheet sources, CONTRIBUTING, this changelog.

### Fixed
- The layout placer crashed with a `TypeError` instead of a clear error when the breadboard
  was full.
- `extract_json` could return non-object JSON. Test-plan regexes could raise `re.error`
  mid-run. Malformed model `fix` dicts could crash the simulated human.
- Web UI XSS through vision findings rendered with `innerHTML`.
